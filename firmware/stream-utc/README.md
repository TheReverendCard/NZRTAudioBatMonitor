# XIAO Stream Field Trial 03

Install on the compact experimental XIAO ESP32-S3 with mic clock D0, data D1, microSD BFF and Wio SX1262.  It listens during the Whangarei night, saves each triggered 192 kHz clip to SD, sends a short Wi-Fi report when possible, and copies the original WAV to the PC during daylight.  LoRa supplies a fallback clock.  The [field audit](FIELD_NOTES.md) gives the comparison with the existing SD and RT firmware, outstanding work and the co-located qualification plan.

## Install and check before deployment

1. On the usual receiver PC start **Start Stream Receiver.cmd**.  Leave the current SD/RT receiver running.  The companion picks up its configured backup directory and private tokens from the existing Bat setup.  It listens on **TCP 8769** on the private LAN.  Permit incoming traffic on the private network if Windows prompts.  If the existing config is elsewhere use **py -3 receiver.py --config "path\to\receiver_config.json" --root "path\to\WiFi_Backup"**.
2. With the card on the PC, run **py -3 configure_card.py E:\ 192.168.1.23** from this directory, replacing the drive and PC LAN address.  This preserves the current Wi-Fi name/password and writes the receiver address and existing token to lines 3 and 4 of **stream-wifi.txt**.  The optional **--config** selects the same private config as in step 1.  Keep this card and file private.  Four lines enable acknowledged reporting and deferred backup.  Two lines retain NTP-only operation; three lines retain the older, always-associated UDP display mode.  HTTP uses the trusted private LAN.
3. In Arduino IDE open **XiaoStream/XiaoStream.ino**.  Select **XIAO_ESP32S3**, esp32 by Espressif **4.0.0**, RadioLib **8.0.0**, **8 MB flash**, **OPI PSRAM**, **USB CDC On Boot Enabled**.  Insert the card and upload to the experimental unit (previously COM14).  No change to the other recorders is required.
4. Serial Monitor, **115200**, newline.  Within 90 seconds of boot in daylight, send **clip**.  Look for **XIAO-STREAM-03**, **ready=1**, **sd=mounted**, **slots=2**, **sd_latched=0**, **clock_sd=saved**, an increase in **saved** and **event_ack**, steady **gaps**, and a **test** on the receiver.  The clip command extends bench listening for two minutes.  If the unit has already gone to sleep, reset it for this test.
5. Send **transfer** to open a two-minute bulk transfer window immediately.  Confirm **wav_ack** increases and the receiver folder **WiFi_Backup/Stream/<device>/<boot>/** contains the WAV and its checksum receipt.  A two-second file is **768,044 bytes**.  Compare its SHA-256 with the WAV on SD when convenient.  For an outage test stop the companion, force another clip, keep the card in place and restart the companion.  Send **transfer** again after the HTTP retry delay.  Expect one new receiver WAV, including when retrying after a reset.  Use this bench check before relying on unattended operation.

## What the monitor does

A candidate opens a 2-second mono PCM16 clip at 192,000 samples/s with up to 250.67 ms preceding the trigger-frame end.  The capture task can fill either PSRAM slot while the writer works.  The event outbox persists its ID, score, kind, trigger uptime and actual pre-trigger sample count.  It attempts a small Wi-Fi report while the remainder of the clip is still being collected.  The writer reads back and compares the entire WAV before publishing it.  If both slots are occupied an alert can exist without a separate WAV.  Serial tests carry their own label.

At dawn the node finishes in-flight work, stops the microphone clock and spends up to two minutes per maintenance window on the upload queue.  After a clean scan it sleeps in stretches of up to four hours, with a five-minute wake guard before the next listening window.  After an incomplete pass it retries in up to 30 minutes.  Sleep requires a usable solar time and an initialized recorder.  With no Wi-Fi time it listens for the local Museum OTD broadcast.  With neither clock it continues listening and saving with boot-relative times.  The first 90 seconds after power-up are available for a bench check even in daylight.

The SD archive is **/STREAM03/<boot>/**.  Keep the entire directory together.  A WAV's filename gives sequence, trigger uptime and type.  Its **.evt** stores metadata; **.crc** holds the original whole-WAV CRC32.  **.ack**, **.utc** and **.done** record receiver acknowledgements.  WAVs stay on the card after transfer.  **clock.csv** maps uptime to UTC within that boot.  **py -3 clip_times.py E:\STREAM03 --output ClipTimes.csv** exports card trigger times and, for intact Field 03 records, estimated WAV start UTC, actual pre-trigger samples, score and receiver WAV acknowledgement.  The receiver stores **.event.json**, **.received.json** (first PC receipt), **.time.json** (when UTC is known, includes estimated acoustic start) and **.wav.json** (SHA-256 and CRC32).  A later same-boot anchor can date earlier audio.  Without any anchor before power loss that boot remains relatively timed.

**health.csv** rows contain uptime_ms, utc_ms, frames, gaps, detections, verified_SD_saves, unconfirmed_clips, alert_queue_drops, event_ACKs, WAV_ACKs, HTTP_failures, outbox_errors, Wi-Fi_on_ms, longest_verified_SD_commit_ms, final_day_checkpoint, END.  Counts are per boot.  The field receiver preserves stable event IDs across retries.  A candidate is an unreviewed detection.

After a card write fault **sd_latched=1** blocks further writes.  The unit uses available clip buffers and the already loaded private network config to try a bounded direct Wi-Fi rescue.  **rescue_ack** counts recovered audio; exhausted slots or unavailable copies count toward **unsaved**.  If the card was absent at boot the unit has no stored network credentials.  Preserve the suspect card and inspect or replace it.  Only with a known-good card in place, send **clear-sd** while idle to release the persistent latch and restart.  A .part or .tmp is an incomplete operation.
