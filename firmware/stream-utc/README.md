# XIAO Stream Power Trial 04

Install on the compact experimental XIAO ESP32-S3 with mic clock D0, data D1, microSD BFF and Wio SX1262.  It listens during the Whangarei night, saves each triggered 192 kHz clip to SD, sends a short Wi-Fi report when possible, and can copy verified WAVs to the PC during daylight when enabled.  LoRa supplies a fallback clock.  The [field audit](FIELD_NOTES.md) gives the comparison with the existing SD and RT firmware, outstanding work and the co-located qualification plan.

## Overnight power trial

Keep your existing receiver IP on the card.  The board makes one bounded Wi-Fi clock attempt per boot (up to 20 seconds).  After that the station starts only for queued reports or enabled audio transfers.  Adjacent reports can share the connection.  An unreachable access point gets up to 12 seconds per event association and a five-minute retry delay.  A failed HTTP request also backs off for five minutes.  Clock refresh can use a working connection.  LoRa receives clock beacons for 135 seconds every 617 seconds while unsynchronised or after an hour without a fresh anchor.  This can delay fallback time acquisition at sites with infrequent broadcasts.  LoRa event transmission is still a separate receiver integration.

An existing three-line card (SSID, password, PC IPv4) sends best-effort UDP alerts to the Trial 02 PowerShell listener on port 8768.  The wire prefix stays compatible and the appended `firmware=XIAO-STREAM-04` identifies this build.  Four lines add the receiver token and switch to the durable HTTP event queue.  **WAV transfer defaults off** in both modes.  To enable daylight WAV backup and the bounded RAM rescue on SD failure, add an empty **stream-wav.on** to the SD root and use the four-line configuration.  Removing that file and rebooting restores local audio and short reports.  The three-line listener accepts reports only.

The PDM mic, I2S DMA, decoder and detector run through every night-time frame.  The capture task blocks between DMA reads.  There is no sampling duty cycle or new amplitude cutoff.  The default front end packs real samples into a 256-point complex FFT and reconstructs the 192 bins required by the model.  An empty **stream-reference.on** on the SD root restores the prior 512-point complex transform at next boot, using identical Wi-Fi policy.  The original PCM decoding and WAV format apply in both modes.

For a same-site comparison, keep the IP, receiver, card, power supply, pulse mode and WAV setting fixed.  Reset the meter at each boot and read accumulated Wh and elapsed time.  Compare about 31 minutes of **night-time listening** per setting, or matched overnight periods.  Compare confirmed co-located passes, capture gaps, report receipts and SD saves.  The final daylight checkpoint or the half-hour health row provides the radio and DSP measurements without Serial Monitor.

## Pulse-train field trial

The recorder evaluates the existing integer score for repeated pulse-like onsets.  In the default **shadow** mode, recording and live alerts still use 1,404.  If a sequence qualifies at the trigger or while its clip is being captured, the card gets a small verified `.p3` marker beside the WAV.  The matching updated receiver stores `.pulse.json` when the audio arrives.  One pass keeps its original event ID.  Pulse support is a review aid and the event keeps its unreviewed label.

For a co-located trial that also **records and reports weaker sequences**, start the receiver from this branch, place an empty file named `stream-pulse.on` at the SD card root, then boot the node.  Status shows `pulse_mode=record`.  Remove the file and reboot to return to shadow mode.  The first qualifying path opens a normal clip and the existing one-second grouping applies to the enabled paths.  A frame-triggered clip uses `_event.wav`.  A clip started solely by the sequence uses `_pulse.wav` and the receiver reports `kind=pulse`.  Older receivers do not accept the new pulse event kind.  Use the matching receiver for the trial.

The provisional rule requires three onsets at or above 702 within 187 frame intervals (499 ms).  Another onset requires eight full frames below 702 (21.3 ms).  The detector clears its history after a capture gap or pause and uses the same 375 scores per second as the frame trigger.  The marker means the running detector qualified at least once during capture, using its continuous history.  A sequence can begin before the saved pre-trigger audio.  The serial counter `pulse_trains` groups qualifications separated by a quiet second.  `pulse_mark_errors` counts failed optional marker writes.  A missing marker on an old clip or after a write fault leaves support unknown.

To replay a reviewed WAV on the PC, use Python with NumPy and the extracted **Xiao_Stream_Recogniser_Trial_01** host kit.  From this firmware directory, run the following with the actual host-kit path.  It prints the maximum score, each distinct score onset and the first frame and sequence trigger times in seconds from WAV start.

```powershell
$wav = "$env:USERPROFILE\Documents\Bat\20261117\XiaoRT20261117\20261118_025416_RT_587d3fed_2_57.wav"
py -3 replay_pulses.py --trial "C:\path\to\Xiao_Stream_Recogniser_Trial_01" $wav
```

## Install and check before deployment

1. On the usual receiver PC start **Start Stream Receiver.cmd**.  Leave the current SD/RT receiver running.  The companion picks up its configured backup directory and private tokens from the existing Bat setup.  It listens on **TCP 8769** on the private LAN.  Permit incoming traffic on the private network if Windows prompts.  If the existing config is elsewhere use **py -3 receiver.py --config "path\to\receiver_config.json" --root "path\to\WiFi_Backup"**.
2. With the card on the PC, run **py -3 configure_card.py E:\ 192.168.1.23** from this directory, replacing the drive and PC LAN address.  This preserves the current Wi-Fi name/password and writes the receiver address and existing token to lines 3 and 4 of **stream-wifi.txt**.  The optional **--config** selects the same private config as in step 1.  Keep this card and file private.  Four lines enable acknowledged reporting.  Two lines enable boot Wi-Fi time.  Three lines enable event-driven UDP reporting.  HTTP uses the trusted private LAN.
3. In Arduino IDE open **XiaoStream/XiaoStream.ino**.  Select **XIAO_ESP32S3**, esp32 by Espressif **4.0.0**, RadioLib **8.0.0**, **8 MB flash**, **OPI PSRAM**, **USB CDC On Boot Enabled**.  Insert the card and upload to the experimental unit (previously COM14).  No change to the other recorders is required.
4. Serial Monitor, **115200**, newline.  Within 90 seconds of boot in daylight, send **clip**.  Look for **XIAO-STREAM-04**, **ready=1**, **sd=mounted**, **slots=2**, **sd_latched=0**, **clock_sd=saved**, an increase in **saved** and **event_ack**, steady **gaps**, and a **test** on the receiver.  The clip command extends bench listening for two minutes.  If the unit has already gone to sleep, reset it for this test.
5. With the four-line card, **stream-wav.on** and the matching receiver, send **transfer** to open a two-minute bulk transfer window immediately.  Confirm **wav_ack** increases and the receiver folder **WiFi_Backup/Stream/<device>/<boot>/** contains the WAV and its checksum receipt.  A two-second file is **768,044 bytes**.  Compare its SHA-256 with the WAV on SD when convenient.  For an outage test stop the companion, force another clip, keep the card in place and restart the companion.  Send **transfer** again after the HTTP retry delay.  Expect one new receiver WAV, including when retrying after a reset.  Use this bench check before relying on unattended operation.

## What the monitor does

A candidate opens a 2-second mono PCM16 clip at 192,000 samples/s with up to 250.67 ms preceding the trigger-frame end.  The capture task can fill either PSRAM slot while the writer works.  The event outbox persists its ID, score, kind, trigger uptime and actual pre-trigger sample count.  It attempts a small Wi-Fi report while the remainder of the clip is still being collected.  The writer reads back and compares the entire WAV before publishing it.  If both slots are occupied an alert can exist without a separate WAV.  Serial tests carry their own label.

At dawn the node finishes in-flight work, stops the microphone clock and spends up to two minutes per maintenance window on the upload queue.  After a clean scan it sleeps in stretches of up to four hours, with a five-minute wake guard before the next listening window.  After an incomplete pass it retries in up to 30 minutes.  Sleep requires a usable solar time and an initialized recorder.  With no Wi-Fi time it listens for the local Museum OTD broadcast.  With neither clock it continues listening and saving with boot-relative times.  The first 90 seconds after power-up are available for a bench check even in daylight.

The SD archive is **/STREAM03/<boot>/**.  Keep the entire directory together.  A WAV's filename gives sequence, trigger uptime and type.  Its **.evt** stores metadata; **.crc** holds the original whole-WAV CRC32.  **.ack**, **.utc** and **.done** record receiver acknowledgements.  WAVs stay on the card after transfer.  **clock.csv** maps uptime to UTC within that boot.  **py -3 clip_times.py E:\STREAM03 --output ClipTimes.csv** exports card trigger times and, for intact Field 03 records, estimated WAV start UTC, actual pre-trigger samples, score and receiver WAV acknowledgement.  The receiver stores **.event.json**, **.received.json** (first PC receipt), **.time.json** (when UTC is known, includes estimated acoustic start) and **.wav.json** (SHA-256 and CRC32).  A later same-boot anchor can date earlier audio.  Without any anchor before power loss that boot remains relatively timed.

**health.csv** rows contain uptime_ms, utc_ms, frames, gaps, detections, verified_SD_saves, unconfirmed_clips, alert_queue_drops, event_ACKs, WAV_ACKs, HTTP_failures, outbox_errors, Wi-Fi_on_ms, longest_verified_SD_commit_ms, final_day_checkpoint, Wi-Fi_starts, UDP_datagrams_sent, reference_FFT (0 packed or 1 reference), CPU_MHz, sampled_frames, sampled_decode_us, sampled_score_us, WAV_upload_enabled, LoRa_RX_ms, END.  Divide the difference in sampled microseconds by the difference in sampled frames to get mean microseconds per 512 samples.  Each frame spans 2,667 microseconds and one in 128 frames is timed.  These are elapsed CPU-task measurements, not component wattages.  Counts are per boot.  The field receiver preserves stable event IDs across retries.  A candidate is an unreviewed detection.

After a card write fault **sd_latched=1** blocks further writes.  With WAV uploads enabled and the authenticated receiver configured, the unit uses available clip buffers and the already loaded private network config to try a bounded direct Wi-Fi rescue.  **rescue_ack** counts recovered audio; exhausted slots or unavailable copies count toward **unsaved**.  If the card was absent at boot the unit has no stored network credentials.  Preserve the suspect card and inspect or replace it.  Only with a known-good card in place, send **clear-sd** while idle to release the persistent latch and restart.  A .part or .tmp is an incomplete operation.
