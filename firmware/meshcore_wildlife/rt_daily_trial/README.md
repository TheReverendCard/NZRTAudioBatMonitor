# Bat Daily RT first-pass trial

Extract all files and run Install_Daily_RT_Trial.cmd once on the Bat Daily PC.  Run Bat Daily as usual.  Installation patches only the completion hook in the current review-first entry point and preserves local edits.  To remove the hook run py -3 install.py --remove.  If a future Daily installer replaces the entry point, run this installer again.

The stage runs under the normal Daily lock after review and report generation.  It reads verified RT daily imports, local FastAvia human grades, recorder snapshots and WAV receipts.  PASS-1 observations use device, session, run and parent sequence.  Shared candidates count once per recording.  Repeated snapshots are deduplicated.  For each qualifying human-graded WAV it replays the locked evolved rule, audible rule and their union.  The run uses Bat Daily's Python with NumPy and SciPy.

Find latest.md, recordings.json (per-recording IDs, grades, shadow outcomes and replay decisions), diagnostics.txt, history/YYYY-MM-DD.json and github_status.txt in Documents/Bat/Daily_Run_Reports/RT_First_Pass.  Outbox holds reports that have not synchronized.  Running again refreshes grades and the local-date report.  The aggregate daily note goes to TheReverendCard/NZRTAudioBatMonitor issue #45 as one comment per NZ day and authenticated account.  Sign in on the receiver PC with GitHub CLI (gh auth login) using an account allowed to comment.  Raw audio, paths, reviewer IDs and raw logs stay local.  Offline or unauthenticated reports retry on the next Daily run.  Keep using the existing Windows receiver startup task.

Field shadow hits describe recorded legacy candidate windows.  An unseen pass between those windows cannot be inferred from a zero.  Unlinked, truncated and missing journal evidence contributes unknown.  Clips recorded in the conservative daytime exclusion 08:00–17:59 NZ, bench clips, other firmware and pre-trial nights are excluded.  Coverage from other recorders requires independent review.  The stage does not claim full-site sensitivity from saved WAVs.

## Inputs for the promotion decision

Place the optional files below in Daily_Run_Reports/RT_First_Pass.  Missing evidence produces a hold.  They cover judgements the current firmware and Daily reviews do not record.

* policy.json may specify {"profile":"evolved","first_night":"20261112"}. The alternative deployable profile is audible; use the board's existing shadow selector to collect field evidence for it. The combined rule is replay-only. Keep the trial start fixed across runs.
* weather.json maps review-night YYYYMMDD to rainy, dry, mixed or unknown. Unlabelled nights remain unknown.
* reviewed_passes.csv columns are pass_id,night,reference,coverage,rt_event_id. Enter one independently confirmed bat pass per ID. Use multiple rows with the same ID for separate RT clips of that pass. Reference identifies the human-reviewed external or local evidence. Coverage is verified, outage or unknown; verified requires actual listening and receiver coverage. Include reference passes with no RT match using a blank rt_event_id. They are unresolved and block promotion. Use the same SESSION:run:seq ID as recordings.json. Count only genuine bat activity. Older training data and ambiguous time-only matches cannot establish field recall.
* health_comparison.csv records comparable-load baseline and candidate sessions. Columns are mode,seconds,dsp_gaps,dsp_drops,clips,incomplete. Mode is legacy or the candidate profile. Use deltas over measured, non-overlapping intervals and count all attempted clips, including incomplete ones. Collect a controlled candidate bench trial for these timings; daytime test audio stays outside the bat evidence. health_review.json binds that file to its reviewer and trial using device, firmware, profile, reviewer, reviewed_noninferior (true), sha256 (Get-FileHash health_comparison.csv, lowercase). Use the review to confirm loads are comparable. Daily checks that all three candidate rates are no higher than baseline.

## Control and evidence policy

Automatic promotion can select an existing first-pass profile on the RT only.  The locked known miss must be retained, 300 independent covered passes must be retained with zero misses or unresolved covered passes, nightly evidence must span multiple nights, at least 80% of graded field noise must be rejected, and the comparative hardware checks must pass.  Unknown noise outcomes stay in the denominator.  This first implementation uses a conservative zero-miss rule.  Different future firmware or model weights require their own versioned replay and field trial.  A missing regression WAV result cannot be manually overridden.  Downstream MLP and SD firmware changes are outside this control path.

When eligible, Daily queues a status request if the last 24 hours lack board readback.  Daily queues pass <candidate> legacy only from verified legacy / candidate status.  It records intent locally and waits for a matching board ACK before reporting application.  Subsequent grade or evidence changes update the report.  Historical confirmation is not a live board query. To revert use the existing remote controls to select legacy active and the candidate in shadow.

Release verification covered the restored daily hook, shared/duplicate journal IDs, the known regression hold, a synthetic eligible trial with a covered and an outage reference, status-to-command-to-ACK transitions, and mocked GitHub retry and comment updates. A local run exercised the complete stage twice with one actual RT WAV and synthetic metadata. Windows execution, receiver commands and daily GitHub publishing from the user's PC require installation and sign-in there. Existing PASS-1 hardware bench results are tracked in PR #46.
