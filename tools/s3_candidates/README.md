# Bat Monitor: S3 candidate outputs v1

Install on the Bat PC: extract this ZIP to a separate folder. Close training and Daily, then run **Install S3 Outputs.bat**. Defaults to %USERPROFILE%\Documents\Bat. For a custom root: py -3 install.py --root "D:\Bat". The installer backs up changed files to Daily_Run_Reports/S3_Install_Backups, preserves the other Daily stages and safely refuses an unfamiliar completion anchor.  Re-running it is supported. If a later Daily update replaces that hook, rerun the installer. To undo, restore the backed-up daily/trainer launchers or copy each .before_s3 launcher's contents back over the original. The sidecar export folder can remain archived.

## What is produced

The installer backfills completed local training runs now. Subsequent successful Review First Daily runs refresh Daily_Run_Reports/S3_Exports/index.json. Recognised trainer .bat/.cmd launchers in TrainingWorkbench, CNNWorkbench and NNWorkbench run it after training; direct Python training or unknown launchers are collected on the next Daily. The installer prints which launchers it attached to. To refresh manually: py -3 "%USERPROFILE%\Documents\Bat\BatDailyTool\S3_Candidates\export_all.py" (use $env:USERPROFILE in PowerShell). Requires the project's existing sklearn TrainingWorkbench and torch CNNWorkbench environments; first-pass exports use only the standard library. No retraining is necessary.

The WAV bundles include wav_frontend.hpp for the bounded RT input (up to two seconds, 192 kHz mono PCM16, converted to 96 kHz), with an S3-optimised FFT and the existing robust pooling. The native XiaoSD 96 kHz path and AviaNZ BMP/image formation still require their own integration. Training accepted longer clips; two seconds is an RT deployment policy, not a guarantee of equivalent evidence.

Under S3_Exports/candidates each content-versioned bundle has a source manifest and file hashes, including the C++ implementation. Models or reports that change create new directories. Unknown families and corrupt/incomplete runs are reported separately without replacing working exports or modifying Daily's recorder results. Check index.json after each update. An export health warning is not a successful export. Only trusted locally trained workbench checkpoints belong under Model_Experiments. Training hashes are integrity checks, not authenticity.

Source exports are not device promotion receipts. All start with promotion_ready=false. This add-on never stages a model, queues a command, changes trial policy or updates either board. Existing PASS-1 field trial promotion of existing firmware profiles is separate. S3 results do not inherit existing desktop/field approvals.

## Build, compare and promote later

Build a specific export in a new directory with 'py -3 build_project.py "<bundle>" "<new-directory>"' from the extracted package. In an ESP-IDF 5.x environment: cd to the generated directory, then 'idf.py set-target esp32s3' and 'idf.py build'. To build all indexed versions in an activated ESP-IDF environment, use python build_all.py "<S3_Exports/index.json>" "<new-directory>". It links each probe and writes a build receipt with image hashes, or a failure. The ESP-DSP dependency is pinned in component/idf_component.yml. These are standalone diagnostic projects, not the installed MeshCore firmware. Never flash a diagnostic onto the field unit as a routine export step. The standalone bench folder builds the audible probe without a trained checkpoint. Initialisation and workspace allocation belong outside capture; use aligned input/storage. DSP FFT tables are shared and must not be resized by another task while running.

Compare the host and S3 scorer on the same held-out **recordings** with their actual preprocessing. Use the input definition and reference waveform tests in VALIDATION.md. Dense models include four deterministic feature probes; CNN includes an expected single-window logit. Evolved's bench is a smoke test, audible's bench times synthetic PCM. Add end-to-end PCM/image frontend parity, live S3/MeshCore build and measured latency, free heap/PSRAM, queue drops, per-pass recall and field shadow evidence before promotion. A candidate.hpp or weights.bin alone cannot establish any of these. Preserve rollback and distinguish XiaoSD's 96 kHz capture from XiaoRT's 192 kHz. Report latency tails and Wh/night with Wi-Fi and LoRa operating.

## Evidence and sources

Host suite: python tests/verify_exports.py (C++ compiler, NumPy/SciPy, sklearn); --upload optionally checks the historical field WAV MLP and BMP CNN checkpoints, with torch installed. Includes frequency-energy checks against NumPy and evolved decisions against SciPy. See VALIDATION.md for what was actually exercised.

Upstream: TheReverendCard/NZRTAudioBatMonitor branches rt-pass1-com8 and bat-daily-rt-trial; owner training packages Shared_Frequency_Model_Trial_v1 and Review First v2.0.4. Aligned S3 kernels depend on Espressif ESP-DSP, Apache 2.0, https://github.com/espressif/esp-dsp. No proprietary AviaNZ model or field audio is bundled. The acknowledged field policy was legacy active, shadow off on 2026-11-13. These exports do not change it.
