# S3 candidate export evidence, 2026-11-13

Scope: six recording-level model families enumerated by the shared-frequency field trial, three PASS-1 profiles, RT-SCORE-1 event ranking and three additional offline replay rules. The stock NZ Bats recogniser and the keep-every-clip replay control are references. The RT-SCORE-1 export reproduces its existing ranking policy. No measurement or claim about battery life, latency improvement or recognition accuracy on unseen bats is made here.

## Tests actually run

- Compiled generated C++ with g++ and compared to sklearn/PyTorch. Five dense family fixtures, each with 64 distinct feature vectors; also tested the supplied trained WAV MLP with 64 vectors and the supplied trained BMP MIL CNN with two 8-window tensors. Absolute probability tolerance 0.00002. The four other current field checkpoints were unavailable: those four paths were exercised with fitted deterministic fixtures, not substitutes for the owner's weights. No synthetic weights ship with the installer.
- Compared the WAV frontend and supplied WAV MLP end-to-end to the original SciPy/sklearn preprocessing and classifier: silence, synthetic noise and six field excerpts. Some were 96 kHz SD recordings resampled to exercise the RT's 192 kHz interface. Largest absolute feature difference 0.00000427, probability difference 0.00000189. The 24,772-byte Wi-Fi binary exactly reproduced SHA-256 b5ddf6282cd269251e8fed77fc4f21646bb0c54da623530772094221998f6c14 from the previous RT update.
- Compared the reference spectra and decisions from 216 frames with NumPy FFT and SciPy band filtering. The fixtures include low-tail and audible interference, crossing both acceptance and rejection branches. Checked the legacy bandpass and complete 150-window baseline on a separate 156-window fixture after priming. Also compared RT-SCORE-1 and its S3 implementation over 75 windows (15 event groups), including harmonic and non-harmonic examples. This tests decisions on controlled input, not emitted field events.
- Generated all thirteen standalone bench sources and cross-compiled each to an Xtensa ESP32-S3 object with Espressif GCC 8.4, ESP-IDF 4.4.7 header tree, S3 target and DSP optimisations enabled, and the pinned ESP-DSP headers. Header/API and target-code compilation passed. This check did **not** link an ESP-IDF project, flash the board, or execute the assembly kernels. The host tests execute the portable math fallback. To get final link evidence, run build_all.py in an activated ESP-IDF 5.x environment. To verify promotion, use measured board/field results on the integrated recorder.
- Installer: applied twice to a copy of Review First v2.0.4 plus the existing two baseline launchers; confirmed idempotence, byte-identical backups, operation without checkpoints and detection of a modified exported file.
- Ownership and repeatability: host torch 2.6.0 and sklearn 1.8.0; the historical MLP was built with sklearn 1.7.2. Its scores and bytes passed the above checks. On the collection PC the exporter uses the installed workbench environments. Keep the trained-model dependencies pinned there.
- Upstream references: PASS-1 4803df3b018df290f7d48a7ac20b877b0a73ac76; desktop RT trial fe9871aba3310a4e76371ba69512e0ee99a478ce; Review First v2.0.4 and Shared Frequency Model Trial v1. The original WAV trainer and the inspected shared-frequency version have identical wav_features and band_pools Python syntax trees. A different source fingerprint can still generate an S3 scorer, but will not automatically generate Wi-Fi weights. Hash metadata proves identity, not analyser accuracy.

## What to compare on hardware

Use legacy active / shadow off as the reference. On a bench or spare RT, replay the same input through the existing and candidate paths with the normal capture buffers, radio and logging enabled. Record the build and bundle IDs, per-window timing distribution and maximum, RAM/PSRAM minimum, dropped windows, input gaps and resets. A 20 ms input window is not a free 20 ms classifier budget. Measure the entire acquisition path, feature extraction and scoring together. Compare passed/missed *reviewed* recordings by recorder, plus false alerts and watt-hours per night. Only then request a separate shadow trial. A source export, successful link or accepted receiver file is not a field approval.
