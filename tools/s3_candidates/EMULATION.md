# S3 emulator and training integrity, v2

**Run on the PC. No board, COM port, receiver token or field firmware update is needed.** The installer wraps recognised Windows trainer entrypoints and updates the Daily completion hook. It preserves originals as `.before_s3.bat` and timestamped backups under `Daily_Run_Reports/S3_Install_Backups`. Inspect the list of patched launchers printed at installation. Unknown launchers, scheduled Python scripts, and direct invocations aren't implicitly protected. See below to integrate one explicitly.

1. Extract the zip, then double-click `Install S3 Outputs.bat` (same action for v1 upgrades). Default root is `%USERPROFILE%\Documents\Bat`. If needed: `py -3 install.py --root "D:\Bat"`.
2. Run your usual training launcher. After the audit refresh and before fitting, the guard verifies eligible original recordings, grade/class, current annotation hash, full BMP/WAV readability, supported WAV rate and length, available WAV receipt fields, and conflicting labels or splits for identical media. A blocked run points to the exact row/file in `Daily_Run_Reports/S3_Exports/Training_Integrity`. Restore the correct original or regenerate the audited snapshot from the legitimate new review. Never delete or relabel a clip just to make a test green. A receiver sidecar is optional: valid PCM does not prove continuous acquisition. This guard reads all eligible media and can take time.
3. Daily and supported trainers refresh `S3_Exports/queue.json`, including old training warnings. `Prediction_Coverage` compares a model's predictions against its original manifest hash when available. Inspect `no_prediction`, `reviewed_positive_below_threshold`, false alerts and invalid rows separately by split. An old/absent manifest is **unknown**, never 100% covered. If a trainer intentionally deduplicated eligible source paths, inspect its duplicate list to reconcile missing predictions. Historical models are not silently retrained or repaired. Unknown grades and missing results are not negatives.
4. Optional automatic simulation on Windows: install WSL2 Linux, [ESP-IDF v5.4.2 with its ESP32-S3 toolchain](https://docs.espressif.com/projects/esp-idf/en/v5.4.2/esp32s3/get-started/linux-macos-setup.html), a native C++ compiler, and the [esp-emu v0.50.0 Linux release](https://github.com/espressif/esp-emulator/releases/tag/v0.50.0) inside WSL. Make sure `esp-emu --version` and `idf.py --version` work with the IDF environment activated. Run **the installed** `BatDailyTool\S3_Candidates\Configure Emulator.bat` once and enter Linux paths. It starts a background test. Later Daily/exports queue tests automatically; `Run Emulator.bat` requests one on demand. No emulator is silently installed. To stop automatic launches, rename `wsl_worker.local.json` in that folder. The WSL launcher is provided for Windows; the emulator execution in this release was tested on Linux.
5. Open `S3_Exports/Emulator/latest.json` and match `index_sha256` to `queue.json`. Use the dated summary if checking an older index. `in_progress.json` is not a completion receipt. Failed builds, missing result IDs, duplicate IDs, non-finite scores, missing completion, decision flips and out-of-tolerance scores require attention. See per-run build/UART logs; a worker startup failure appears in `S3_Exports/Emulator_worker.log`. Unknown families/unavailable weights cannot pass. Partial `--only` suites save a separate latest_subset.json. Passing receipts are cached by export contents, runner and tool identity. No model promotion is automatic.

Native Linux/WSL, after sourcing the IDF environment:
```sh
python emulator_gate.py "/path/to/Bat/Daily_Run_Reports/S3_Exports/index.json" --emu /path/to/esp-emu
```
Optional `--dsp /path/to/clean/esp-dsp` selects a clean checkout at the pinned commit in component/idf_component.yml. Otherwise the IDF component manager fetches the pinned dependency. All builds are disposable diagnostics. Never flash the diagnostic image onto a deployed monitor.

**Developer integration:** before calling an unwrapped trainer (after its frozen input manifest exists), invoke `training_guard.py --root ... --modalities bmp wav` in the training Python environment (Pillow required for BMP), or specify just its modality. Stop fitting on a nonzero code. After successful fit invoke `export_and_queue.py --root ...`. The guard archives each validated CSV by its SHA-256 under S3_Exports/Frozen_Manifests so future audits can use the exact snapshot. It does not archive recordings. Grade 3/unknown should stay separate from binary training/evaluation.

**Private recording replay:** in the matching trainer environment, use `recording_replay.py prepare BUNDLE WEIGHTS NEW_PACK MEDIA [MEDIA ...]`; for BMP CNN supply `--cnn-script /path/to/cnn_bmp_mil.py`. Use trusted local checkpoints and trainer scripts. In the IDF environment use `recording_replay.py run BUNDLE PACK NEW_OUTPUT --emu /path/to/esp-emu`. Cases are ordered, input-bound, and must all produce a result. Prepare returns nonzero for damaged/excluded inputs; the valid part of the pack can still be tested and the final run reports partial coverage. Split larger sets into packs of at most 7 MB of prepared input. Keep private: generated bench images, tensors, raw PCM, and source paths may contain your recordings. WAV replay tests continuous chunks up to 2 s, not a complete firmware event scheduler. BMP CNN replay supplies desktop-prepared tensors (8 windows on the tested model); there is no live-mic-to-BMP frontend claim.

**Field loss:** use `py -3 health_coverage.py journal.txt [journal.zip ...] --out health.json` on J4 logs. It deduplicates overlapping health records by session/run/UTC, reports observed gap counters, and keeps conflicting/missing intervals unknown. No data is recovered by replay. Run the same known PCM on the real S3 with the production acquisition and radio tasks; compare sequence continuity, queue high-water, DSP drops, capture/score result counts, worst/p99 compute time and human-reviewed positives with the shadow worker off/on. Use at least one busy night and include weak calls. Bench throughput and virtual time are not power, DMA, radio contention, or real-time latency measurements.

## Reproduced 13 November 2026

See the bundled evidence directory. The v0.50.0 emulator booted ESP-IDF 5.4.2 Xtensa images with 8 MB of virtual PSRAM. **2,016 indexed numeric/gap results across 13 profiles**: six first-pass profiles (328 evaluated windows and three intentionally missing slots each), nine event-score values, four dense vectors for each of five model families, and one CNN logit. Nominal first-pass parity is against the portable implementation of the same rules; it is not independent evidence of sensitivity. Two fitted checkpoints were available (WAV MLP, BMP CNN); four trained adapter families used fitted **fixtures**, not the owner's weights. Stock AviaNZ remains a desktop reference. Missing result, duplicate ID, NaN, missing completion and bad media are exercised by negative tests.

On real media, the WAV MLP and desktop agreed on all six chunks from two 96 kHz SD recordings; the S3 replay used 192 kHz resampled input and did not acquire new ultrasonic information. Two deliberately damaged recordings in this pack were unscorable. The BMP CNN and desktop agreed on four privately prepared tensors, including grade-5 AR4 recordings 20261106_204727 and 20261108_031059. All four were flagged; three scores were about 0.414 against a threshold of 0.4084. This small convenience set has no prevalence or precision interpretation. A separate read-only audit of the 14 uploaded WAVs found nine readable, four truncated and one without a WAV header.

The two historical model reports each list 57 annotations changed since audit, not 114 proven distinct missing recordings. The WAV MLP's **previously diagnosed** desktop test split detected 8/9 reviewed positives. Its grade-4 miss was event_20261102T071642Z_00007 (0.9771 vs 0.9833). The CNN missed one of 28 validation positives (20261030_233745, grade 4) and flagged 30 validation negatives. Those original missed files were not in the four-image/two-intact-audio emulator sample. Do not tune to recover those specific test examples and then report the same dates as a blind test.

In one uploaded Nov 13 journal archive the deduplicated telemetry has 38 health intervals, 31 reporting gaps, 4,165 summed dsp_drop_delta and four separations longer than 90 seconds within a session/run. Units are firmware-reported drops, not known bat calls. The emulator reproduced no field lockup. This is evidence to prioritise a hardware-in-the-loop load test, not evidence to lower a trigger threshold.

Build corrections: fixed misleading indentation that IDF treated as compile errors and moved floating-point constructors for the evolved/RT-SCORE-1 bench objects inside the running task (a pre-task constructor caused a coprocessor panic in the diagnostic). No production firmware source, capture setting, model threshold or field model was modified.
