# Run the GUARD-2 comparison over USB

Extract the ZIP. Close miniterm (Ctrl+]) and leave the WiFi receiver running. Double-click **Run_RT_Compare.cmd**. Uses the existing Python and pyserial on Windows and COM8 by default. For another port, in PowerShell from this folder use `.\Run_RT_Compare.cmd --port COM9`. No build, flash, model promotion or receiver update. Start from automatic schedule, bench off, periodic diagnostic samples off. The runner refuses an active bench/periodic configuration, so it cannot accidentally clear it.

The runner checks the board identity, prepares bench mode once, and runs capture, score, and send in that order. Expect roughly 26 seconds per stage plus queuing or network time. Each stage gets a dedicated two-second diagnostic clip. Explicit WAIT means retry, not accepted. The runner waits for TIMING, COUNTERS, matching END, and this session's diagnostic clip ACK before advancing. A post-END ACK is valid, and a live journal ACK is not a clip ACK. During normal operation it sends stop once at the end and verifies bench OFF. On timeout or cancellation it attempts the same cleanup. If interrupted by disconnect, reconnect in miniterm and send `nzrt compare stop`. Opening the serial port can reset some adapters.

Under `Documents\Bat\Daily_Run_Reports\RT_Compare\<UTC timestamp>\` the tool saves `serial.txt` and `summary.json`. A custom Bat root can be set via NZRT_BAT_ROOT or pass --output-root. A completed measurement does not certify zero audio loss. Inspect stage counters (drops/gaps/dma_ovf), queue_peak, dsp_peak_us, journal_max_op_us and the diagnostic clip's continuity. A quiet 20-second measured window does not overrule gaps in a longer loaded run.
